# 人物场景替换 skill

本 Skill 以已有视频为运动和时间轴母版，根据用户本次真正指定的任务，替换一个人、多个不同人物、人物与背景，或只替换背景。

## 先判断本次模式

| 模式 | 用户意图 | 参考素材 | 处理方式 |
|---|---|---|---|
| A. 单人替换 | 只替换一个指定人物 | 1 张人物图 + `<Video 1>` | 只定义该人物；可考虑单人物换人 LoRA |
| B. 多人替换 | 同时替换两个或更多人物 | 每名人物各 1 张图 + `<Video 1>` | 每个别人物独立 `<Subject N>`；关闭只适合单人的换人 LoRA |
| C. 人物 + 场景 | 替换人物并同时替换背景 | 人物图 + 1 张纯场景图 + `<Video 1>` | 人物和背景分别定义；按素材数量决定 LoRA |
| D. 单独场景 | 只替换背景，人物和动作保持原样 | 1 张纯场景图 + `<Video 1>` | 不定义人物替换；关闭换人 LoRA 和锁脸 |

还可以组合：单人 + 场景、多人 + 场景、只替换某一部分人物。Skill 必须服从用户本次明确指定的范围，不把没有参与的素材自动加入。

## 素材映射

`<Video 1>` 永远是待编辑的目标视频，负责时长、构图、机位、动作、口型、节奏、对白和原音轨。

人物参考图只提供身份与外观，包括脸型、五官、发型、服装和体型。场景参考图只提供背景结构、地面、光线、色彩和空间关系。

如果用户没有说明“哪张图替换视频里的谁或什么”，只问一个最短问题：

`请确认每张 Picture 分别替换视频里的哪个人物或场景。`

不要自行假设所有人物图都必须使用，也不要在缺少某个 `<Picture N>` 时仍然引用它。

## 各模式要点

### A. 单人替换

- 只保留这一名人物和 `<Video 1>`。
- 可以使用 `h3_character_swap_pro4500_1000`，强度通常为 `1.0`。
- 单人物可考虑开启锁脸；如果动作或轮廓被过度拉向参考图，关闭锁脸或降低原片参考强度。
- 提示词只定义 `<Subject 1>` 和 `<Video 1>`。

### B. 多人替换

- 每个别人物必须使用独立 `<Subject N>` 和 `<Picture N>`。
- 在正文中明确每个人物在画面中的左右位置、前后关系、动作和说话状态。
- 关闭 `h3_character_swap_pro4500_1000`，避免 LoRA 只绑定第一个人物。
- 关闭锁脸，避免同一张脸贴到所有人物。
- 不要只写“将所有人物替换为 Picture 1”；不同人物必须分别映射。

### C. 人物 + 场景

- 人物和背景分别定义，背景环境使用独立的 `<Subject N>`。
- 场景图必须只提供环境信息，不把其中的人物当成额外替换对象。
- 多人时关闭单人换人 LoRA；单人时可以使用。
- `detailed_description` 同时写明人物动作和背景环境变化。

### D. 单独场景

- 只定义场景 `<Subject N>` 和 `<Video 1>`。
- 原视频中的所有人物的身份、数量、服装、动作、走位和对白全部保留。
- 关闭换人 LoRA 和锁脸。
- 不创建人物 `attribute_transfer`，背景使用 `attribute_transfer` 或 `fully_preserved`。

## 推荐节点参数

- 主模型：`minimax_h3_hybrid_fl2va_ref2va_b25-49-int8`
- 模式：`Ref2VA 全能参考`
- 换人模式：涉及人物替换时开启；只替换场景时可保持换人参考通路，但关闭人物专用 LoRA
- 原片参考强度：`0.12-0.20` 用于强身份覆盖，`0.25-0.40` 用于更强动作保持，只换场景时通常使用 `0.25-0.40`
- 参考图尺寸：`1K`；需要脸部和服装细节时可用 `1.5K`
- 输出：至少 `480P`，宽高比优先跟随原片
- 采样器：`er_sde`
- 调度器：`simple`
- 步数：`25`；细节不足时可升到 `32-40`
- 降噪：`1.0`

## 台词识别与口型同步

如果上游接入 `AICG3D SKILLS · 视频台词识别` 的输出，必须把识别结果视为原视频已经存在的真实对白，而不是新写台词。

1. `S1/S2/S3...` 是原视频说话人编号，必须按用户提供的 `S1 -> Picture 1`、`S2 -> Picture 2` 映射到对应的 `<Subject N>`。
2. 时间码必须使用识别结果，不得把所有台词集中到首镜，也不得改变说话先后顺序。
3. 识别出的台词正文只有原语言和原标点，必须逐字写入 `<d>[Chinese]原文</d>`；不得翻译、润色、补句或扩写。
4. 每个台词块必须写在对应时间段的 `detailed_description` 内，并同时写出该 `Subject` 的说话动作、口型和表情；不要另开“对白列表”。
5. 没有接台词识别结果、也没有用户明确提供的逐字台词时，禁止生成 `<d>` 对白。任务说明、问题、素材用途、旁白和“跟谁换谁”都不得写成人物台词。
6. 复用原音轨时，`overall_soundscape` 写明 `<Audio 1>: fully_copy - 原视频音轨、语言、语速和停顿完整复用`；台词文本只用于锁定语言内容、说话人和口型节奏，不改变原始音轨。
7. 说话人没有正确映射时，不要猜测。保持原视频口型和动作同步，并在状态中提示用户补全 `S1/S2` 对应关系。


## 输出格式

只输出六段，字段名和顺序固定：


```text
subject_definitions:
summary:
retention_analysis:
detailed_description:
overall_soundscape:
non_diegetic_music:
```

不要输出解释、分析、七段式栏名、Markdown 代码围栏或工作流术语。

## 写作规则

- `subject_definitions`：只定义本次使用的 `<Picture N>`、`<Subject N>` 和 `<Video 1>`。
- `summary`：以 `[video editing + audio reuse]` 开头，简述本次替换了哪些人物或场景。
- `retention_analysis`：`<Video 1>` 使用 `fully_preserved`；被替换人物或背景使用 `attribute_transfer`；未参与替换的内容不定义。
- `detailed_description`：`[Shot 1]` 不写时间码；后续镜头使用 `At MM:SS.mmm, ...`；写清人物位置、说话动作、口型、镜头和背景变化。
- 用户没有提供确切台词时，禁止生成 `<d>` 对白，禁止把素材说明、问题、任务描述或旁白改写成人物台词。
- 用户或台词识别节点提供台词时，逐字保留原语言、原标点和时间码，格式为 `<d>[Chinese]原文</d>`；说话人编号按识别结果或用户映射为 `(S1)`、`(S2)`。
- 复用原音轨且有逐字台词时，在对应时间段写入 `<d>` 原文，并写“说话动作和口型与 `<Video 1>` 同步”；没有逐字台词时才只描述口型。
- 正文只写实际存在的画面与声音，不写否定式指导，不把多视图设定板的排版写进目标画面。
