# 3D白模人物场景替换 Skill

本 Skill 只处理“视频已经转成 3D 白模”后再做人物、背景替换的任务。白模不是最终画面外观，只负责锁动作、口型、站位、镜头和时间轴。

> 2026-10-17 实测结论：白模只作为辅助。正式人物替换优先直接使用原视频作为动作母版。单人使用 Character Swap LoRA 1.0；多人必须按人物顺序分两遍，每遍只连接一张人物参考。只换背景且要求人物像素完全不变时，使用 `SMS ③B 静态换景·人物像素锁定`。详细参数和实测见 [research-and-redesign.md](references/research-and-redesign.md)。

## 先选模式

| 用户目标 | 白模节点设置 | 默认参考图顺序 | 核心结果 |
|---|---|---|---|
| 只替换一个或多个人，保留原场景 | 保留原视频场景=开，绿色背景=关 | 前几张是人物图 | 只替换人物，背景保持原视频 |
| 替换一个或多个人，同时替换背景 | 保留原视频场景=关，绿色背景=开 | 人物图在前，场景图放最后 | 人物和背景都替换，最终无绿色 |
| 只替换背景，保留原人物 | 优先使用原视频；若使用白模，必须另给原人物身份参考 | 场景图；如有人物身份图，则场景图放最后 | 背景替换，人物身份和动作保持不变 |
| 只替换单人 | 按是否换背景选择上面两种白模模式 | 单人图在前，场景图放最后 | 只定义该人物，未参与人物不要引用 |

如果用户明确指定了 Picture 编号，以用户指定为准。不要定义或引用没有参与本次任务的 Picture。

## 彩色人物 ID 锁定

白模节点开启“逐人锁定颜色”时，默认调色板为：

```text
蓝色   = Subject 1
红色   = Subject 2
绿色   = Subject 3
品红   = Subject 4
青色   = Subject 5
黄色   = Subject 6
```

- 人物穿插、遮挡、移动或左右换位时，必须按颜色 ID 锁身份，不能按画面左右临时换人。
- 用户做“替换1、替换2”时，必须把替换1绑定到蓝色 ID，替换2绑定到红色 ID；更多人物依此类推。
- 颜色 ID 只用于锁定身份。最终画面不能出现蓝、红、绿、品红、青、黄色块，必须恢复参考图中的真实肤色和服装。
- 白模未开启逐人颜色时，才使用“左侧人物=Subject 1、右侧人物=Subject 2”的位置映射。

## 素材职责与默认编号

- `<Video 1>`：白模动作母版，只提供动作、口型、身体朝向、人物位置、镜头运动、时长和原始音轨。
- `<Picture 1>`：第一个要替换的人物；单人任务默认对应蓝色 ID / Subject 1。
- `<Picture 2>`：有两人替换时对应红色 ID / Subject 2；单人换背景时，它通常是场景图。以用户实际顺序为准。
- `<Picture 3>`：双人及多人换背景时的场景图；单人任务中场景图通常是 `<Picture 2>`。
- 多人任务按“人物图在前、场景图最后”排列：`Picture 1..N` 是人物，`Picture N+1` 是场景。
- 未参与本次任务的 Picture 不定义、不引用。

如果用户说明了不同的 Picture 编号或颜色对应关系，以用户说明为准。多人任务必须逐个说明 Picture、颜色 ID 与 Subject 的对应关系。

## 背景替换规则

- 需要换背景时，场景图负责建筑结构、地面、树木、光线、色彩和空间关系，整体替换 `<Video 1>` 的背景环境。
- 绿幕白模只负责动作和身份区分；最终画面必须彻底移除绿色背景、绿幕边缘和抠像残留。
- 保留原视频场景时，不要定义场景 Subject，也不要让模型重新生成背景。
- 只替换背景时，人物身份、人数、服装、动作、口型、走位、镜头和声音必须保持原视频一致。
- 背景透视、主光方向、地面位置和遮挡关系要与原镜头一致，不能让背景像贴图一样漂移。

## 推荐节点配置

### 直接源视频路线（最终推荐）

- 单人：Ref2VA + Character Swap LoRA 1.0 + Turbo LoRA 1.0，`er_sde/beta`，8 步；`source_reference_scale=1.0`。
- 多人：按人物分两遍顺序替换，每遍只给 Character Swap LoRA 一张人物图，不要关闭 LoRA 后联合采样。
- 人物+背景：先按单人/多人完成人物替换，再用静态换景节点替换背景并锁定已替换人物。
- 只换背景：优先使用静态换景节点，人物身份、服装、动作和口型保持原视频像素。
- 3.75 秒/90 帧、24fps、短边 384 预览，正式短边 640。

### 白模辅助路线

- 最大人物数设为本次实际要替换的人数；双人任务通常填 2，避免路人和重复跟踪被着色成额外人物。
- 彩色白模作为动作母版时，原片参考强度建议从 0.10 到 0.20 起步；强度过高会让模型直接照抄蓝红白模。
- 人物替换 LoRA 使用 `h3_character_swap_pro4500_1000`，通常强度 1.0 到 1.2；不要只挂加速 LoRA。
- 逐人颜色强度建议 0.40 到 0.55：既能锁定身份，又不会把蓝红颜色当成最终服装。
- 双人替换建议至少 25 步；4 步实时预览只是中间帧，不能当作最终替换结果。

## 禁止进入最终提示词的内容

- 白模的灰白材质、网格表面、3D 模型外观。
- 绿色背景、绿幕边缘和抠像残留。
- 三视图、角色设定板、人物拼图或参考图排版。
- 白模逐人标识色，例如蓝、红、绿、品红、青、黄色块；最终成片必须恢复参考图中的真实肤色和服装。
- Skill 规则、检查表、模板说明、文件名或工作流术语。

## 台词与口型

- 没有连接台词识别、也没有用户提供的逐字台词时，禁止生成 `<d>` 对白。
- Skill 规则、检查项、模板句子和说明文字都不是台词，禁止把它们放进 `<d>`。没有真实台词时间线时，最终输出的 `<d>` 数量必须为 0。
- 没有逐人台词时间线时，禁止写“某一个人全程说话”或把说话状态固定给某一侧。每个人物只继承原视频同一位置或同一颜色 ID 的说话/不说话时序与口型，身份和口型都不得互换。
- 有真实台词时间线时，保留原语言、原标点和时间码，并映射到正确的 Subject。
- 复用原视频音轨时，说话动作、嘴型、语速、停顿和说话先后顺序必须与 `<Video 1>` 同步。
- 不把任务说明、场景说明、旁白或“替换哪个人”写成人物台词。
- 最终自检：如果某个人物没有说话，就必须保留闭嘴、停顿、倾听或原有静默状态；不得因为另一侧在说话而跟着张嘴。

## 输出格式

只输出以下六段，字段名和顺序固定：

```text
subject_definitions:
summary:
retention_analysis:
detailed_description:
overall_soundscape:
non_diegetic_music:
```

不得输出解释、分析、七段式栏名、Markdown 代码围栏或额外前后缀。
